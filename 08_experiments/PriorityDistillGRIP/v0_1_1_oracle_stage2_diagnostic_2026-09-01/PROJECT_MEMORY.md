## Diagnostic logic

The v0.1 oracle path exposes the answer as the final path node in every training row. Therefore low Stage-1 loss can mean copying, not graph-free internalization. v0.1 also switched suddenly from path evidence in Stage 1 to answer-only prompts in Stage 2, with only about 103 optimizer steps and a decaying learning rate.

This version records a curve at `initial`, `stage1_end`, and every Stage-2 epoch. It evaluates:

- `graph_free`: no path/evidence, the actual deployment condition;
- `oracle_evidence`: gold path visible, diagnostic-only condition.

Interpretation:

- high evidence / low graph-free = shortcut dependence;
- graph-free recovery across epochs = Stage-2 undertraining/scheduler issue is material;
- no recovery after 8 epochs = change evidence serialization and add anti-copy controls before any new prioritizer.

## 2026-09-01 diagnostic result

Run `wsl3090_oracle_stage2_diagnostic_20260901_01` completed. Stage-1 oracle-evidence accuracy was 1.0000 on validation/test while graph-free accuracy was 0.0000, confirming that Stage 1 fit is evidence-dependent rather than graph-free internalization. During answer-only Stage 2, graph-free test accuracy rose to 0.1731/0.2436/0.2628/0.2756/0.3590 by epochs 1–5, with validation peaking at 0.3224 at epoch 5. It then degraded to 0.3013 test and 0.2895 validation at epoch 8; oracle-evidence accuracy also fell to 0.4167/0.4408. The result supports Stage-2 undertraining as a material cause of the v0.1 failure, but the non-monotonic late-epoch curve shows that simply extending training is not enough. Use validation-based checkpoint selection, lower Stage-2 LR, possible Stage-1 replay, and anti-copy evidence formats in the next controlled revision. Do not implement learned prioritizer yet.
