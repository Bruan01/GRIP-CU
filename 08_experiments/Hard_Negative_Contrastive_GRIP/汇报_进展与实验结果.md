**日期**：2026-09-10

## 0. 一句话结论

结构感知负样本（`tail_range` / `path_local`）**打不进模型真实决策集合**，不宜作为训练主信号。把负样本改成题目自带的官方 10-way 干扰项后，零训练硬度检查通过，但 **smoke 对比训练没有涨生成 EM**：listed 对比把列表内误选几乎压没（26→1），同时把列表外乱生成从 21 抬到 53，整体 EM 从 51.0% 掉到 43.8%。当前停在「对比目标有效、生成目标受损」的决策点，**不要开 path/tail_range 的 B2–B10，也不要把 smoke 当论文结果**。

---

## 1. 研究问题与定位

**问题**：在 GRIP「图写入 LoRA、推理不再喂图」的设定下，用结构感知硬负样本做图内对比学习，能否让模型更好地区分正确答案与易混淆关系，同时保住原生成目标？

**工作标题**：Contrastive In-Parameter Graph Reasoning with Structure-Aware Hard Negatives（工作名，不是 novelty 声明）

**文献结论**（`RESEARCH_REVIEW.md`，2026-09-02）：组合式创新，单点不新。

| 组件 | 最近先例 | 本项目差异 |
|---|---|---|
| 结构负样本 | SANS（k-hop 邻域负实体） | 搬到关系预测 + LLM |
| 对比 loss | SimKGC InfoNCE | 保留 GRIP 图 adapter，不改表示学习骨架 |
| 生成式硬负样本 | ACL 2023 Findings | 第一版不用第二生成器，用确定性图启发式 |
| 图写入参数 | GRIP（KDD 2026 / arXiv:2511.07457） | 原目标只有生成 likelihood，没有候选级 ranking |

可投层级按设计时判断是 **analysis + extension**（workshop / findings / 短文），不是主会 full paper。H4（图知识由 adapter 承载）需要多图 shuffled 控制，NELL23K 单图做不了完整机制声明。

五个假设：

- **H1**（方法）：对比训练提高候选 MRR / Hits@1，且生成 EM 不明显掉。
- **H2**（前提）：结构负样本比 uniform 更难。
- **H3**：三家族合用优于单家族。
- **H4**（机制）：正确 adapter 相对关闭/打乱 adapter 的分数 margin 变大。
- **H5**：收益不是多算几步或多样本带来的。

H2 不成立则 H1 没有理由；H1 不成立则 H4 不可解释。

## 4. 实验过程与结果

### 4.1 实验 A：候选审计（零训练，数据卫生）

**做法**：在 smoke 160 题（train 64 / val 32 / test 64）上，为每题生成各家族负关系；过滤全部已知 train/val/test 三元组；检查泄漏与家族计数。

**对齐前**（RecurrentGRIP 自带 10-way）`results_nell23k_audit.json`：

| 家族 | 候选数 | 泄漏 |
|---|---|---|
| uniform | 640 | 0 |
| tail_range | 485 | 0 |
| path | 523 | 0 |
| random | 640 | 0 |

三大家族非零，过滤通过。这只说明「能造出合法负三元组」，不说明它们更难，也不说明它们等于模型会犯的错。

**对齐后** `results_nell23k_audit_aligned.json`：listed **1440**（每题满 9 个干扰项）、surface 601、hallucinated 640，泄漏仍为 0。

---

### 4.2 实验 B：H2 零训练硬度门禁

**指标定义**：负分数越高、正负 margin 越小、Hits@1 越低 = 越难。配对检验看「该家族是否比 uniform 更难」。

#### B.1 第一次打分（2026-09-03，已作废为证伪依据）

用失败的 attention-LoRA pilot adapter（correct EM **4.5%** < 关 adapter **22.7%**），且打分前缀没有套 GRIP 的 `"Given the context graph titled ..."` 模板。结果：tail_range 50.7%、path 42.5%，看起来像「结构负样本不更难」。这次实验不干净——adapter 本身在拖后腿，不能拿来否证负样本设计。

后续 RecurrentGRIP `quick01_storage_quick`（MLP LoRA 全层）把前提翻过来：

```
correct adapter  47.8%
no adapter       22.5%
```

「图写进参数」在本环境成立。H4 不再被那条坏基线直接否掉；H2 必须在这份能存图的 adapter 上重测。

#### B.2 Storage adapter 重测（2026-09-09）

- Adapter：`quick01_storage_quick/adapter`
- 160 题逐候选算归一化续写分数
- 对照：`--control correct` vs `--control none`

| 家族 | adapter 负分数 | adapter margin | adapter Hits@1 | base 负分数 | base margin |
|---|---|---|---|---|---|
| uniform | -1.658 | 1.373 | 94.4% | -4.588 | 3.777 |
| tail_range | -1.625 | 1.330 | 92.1% | -4.573 | 3.727 |
| path_local | -1.727 | 1.453 | 92.5% | -4.708 | 3.899 |
| random | -1.990 | 1.706 | 94.4% | -5.164 | 4.353 |

配对「是否比 uniform 更难」：

| 条件 | tail_range | path |
|---|---|---|
| correct adapter | **59.9%**（91/152） | **43.2%**（63/146） |
| base model | **47.4%**（72/152） | **43.8%**（64/146） |

按 split（adapter）：train 60.3% / val 59.4% / test 59.7%。overall tail_range z=2.43，p≈0.015；**test-only** 37/62，z=1.52，p≈0.13。path 所有 split 都低于 50%。

**判读**：

1. **path_local 明确失败**，adapter 和 base 都觉得它比 uniform 更容易。关掉，不要再当硬负样本。
2. **tail_range 方向对、幅度弱**：相对 base 的 47.4% 抬到 59.9%，三个 split 一致，但 test 单独不显著，Hits@1 只从 94.4% 掉到 92.1%。不够开 B2–B10。
3. Adapter 这次确实把图写进去了：正样本分数从 none 的 -0.811 升到 -0.285。旧跑「adapter 判别力下降」不再适用。
4. 绝对 Hits@1 虚高：题目文本自带 10-way，audit 另造的负关系不一定出现在列表里。相对比较仍可用，不能当训练收益预期。

旧结论里「base model 也证伪所以设计本身不成立」不成立——base model 看不见图结构。真正干净的否证对象只剩 path_local；tail_range 是未决弱信号。

### 4.3 实验 C：官方 10-way 对齐 + 错误覆盖（改负样本瞄准点）

**发现的协议问题**：官方 GRIP 用 `process_raw_data.py --datasets nell23k --seed 2026` 只给 valid/test 抽 10-way；RecurrentGRIP 用另一套 per-subset RNG。同一 `question_id` 的列表几乎完全不同。

| 集合 | eval 题数 | 与官方 10-way 完全相同 | 平均 Jaccard |
|---|---|---|---|
| smoke 96 val/test | 96 | **0** | 0.081 |
| pilot 640 val/test | 640 | **0** | 0.074 |

对齐产物：`data/nell23k/recurrent_relation_prediction.aligned.json`（及 `_pilot`）。Train 题官方没有列表，保持 RecurrentGRIP 10-way。

**更关键的是：结构负样本几乎不等于模型会犯的错。**  
对照 `quick01_storage_quick` 640 题生成（correct EM 47.8%），334 个错误切成三类：

| 错误类型 | 数量 | 含义 |
|---|---|---|
| 列表内误选 | 174 | 在 10-way 里选错了 |
| 词表内、列表外 | 70 | 生成了真实关系，但不在这 10 个里 |
| 真 OOV | 90 | 造了词表里没有的字符串（常见前缀混淆） |

各家族打中这些错误的比例：

| 家族 | 列表内 174 | 词表内列表外 70 | 真 OOV 90 |
|---|---|---|---|
| 评测题自己的 10-way / `listed` | **174/174** | 0/70 | 0/90 |
| 官方 10-way 去套已经跑完的 quick01 | 9/174 | 8/70 | 0/90 |
| surface（近形关系） | 14/174 | **17/70** | 0/90 |
| hallucinated（先验拼接） | 0 | 0 | **0/90** |
| tail_range | 11/174 | 7/70 | 0/90 |
| path_local | 12/174 | 18/70 | 0/90 |
| uniform / random | 0 | 0 | 0 |

Audit 160 题与 quick01 val/test 重叠 96 题（对 37 / 错 59）：预测落在 tail_range 仅 2/59，path 1/59。题目 10-way 被这两个家族覆盖也只有约 2%。

**因此改瞄准点**：

1. 主负样本改成 `listed_relation`：评测时那份 10-way 的全部 9 个干扰项，覆盖约 52% 的生成错误。
2. 对齐官方列表是评测协议卫生，不是给已经跑完的 quick01 补覆盖。
3. `surface_relation` 作第二家族，覆盖「生成了真实关系但不在列表里」（17/70）。
4. 先验幻觉字符串召不回真 OOV（0/90）。OOV 是解码问题：约束生成到 10-way，或挖模型自己的 rollout。
5. path / tail_range 不再当主硬负样本。

### 4.4 实验 D：对齐后 listed vs uniform 卫生检查（仍零训练）

题目换成官方 10-way 写进 prompt 之后，再打一次续写分。

| 家族 | adapter 负分数 | adapter margin | adapter Hits@1 | base Hits@1 |
|---|---|---|---|---|
| uniform | -1.650 | 1.353 | 96.9% | 96.9% |
| **listed** | **-0.957** | **0.661** | **51.3%** | **38.1%** |
| surface | -1.878 | 1.580 | 92.4% | 93.7% |
| hallucinated | -5.245 | 4.949 | 100% | 100% |
| tail_range | -1.634 | 1.327 | 94.7% | 96.1% |
| path | -1.697 | 1.409 | 91.8% | 95.2% |

listed 比 uniform 更难：adapter **159/160 = 99.4%**（train 64/64，val 31/32，test 64/64）；base **160/160**。

**读法**：检查通过——负样本终于打进决策集合，Hits@1 从 97% 掉到 51%，这才像「真会搞混」。**但这不是创新。** 关掉 adapter 之后 listed 仍然 160/160 更难。难，主要是因为选项印在题目上。Adapter 有一点判别力：listed Hits@1 从 base 的 38% 升到 51%。对比训练如果有用，是把剩下那一半列表内混淆再压下去，并且不能牺牲生成 EM。

### 4.5 实验 E：第一次对比训练（smoke，2026-09-09）

这是目前唯一一次真正训练。方法门禁，不是论文结果。

**设计**：共享 Stage 1 图存储，再 fork 两条 Stage 2，生成目标算力对齐（都跑满 10 个 QA epoch，无 S2 early stop）。

```
Stage 1（共享）  图 context 写入 MLP LoRA
        │
        ├─ B1      只生成 loss          = 原版 GRIP
        └─ listed  生成 + 10-way InfoNCE
```

**配置**：

| 项 | 值 |
|---|---|
| 数据 | aligned smoke：train 64 / val 32 / test 64 |
| 模型 | Qwen2.5-0.5B，本地 cache |
| LoRA | r=4，α=8，`down_proj/up_proj/gate_proj` |
| Stage 1 | 44,821 条 context，1 epoch，88 step，约 9.6 min，train loss 1.285 |
| Stage 2 | 64 QA，10 epoch，lr=1e-3，λ_candidate=1.0（listed）/ 0（B1） |
| 评测 | greedy 生成 exact match；同时统计错答是否落在 10-way 内 |
| GPU | RTX 3090 24GB；seed=2026 |
| 运行目录 | `results/runs/20260909_listed_vs_b1_smoke_listed_vs_b1_smoke` |

**过程插曲**：listed 第一轮按 batch=8 打 10-way 续写分，Accelerate 把 logits 转 fp32 后 **OOM**。修复：评分走 `unwrap_model`，避开 fp32 logits 路径；listed 以 batch=1、gradient checkpointing 从同一份 s1_adapter resume。B1 已在 OOM 前训完，两条臂仍共享同一 Stage 1。

listed 训练约 15.5 min；末步 generation loss 0.463，**candidate loss 0.0019**（InfoNCE 几乎被压到 0，说明列表内区分已经学会）。B1 约 12 s，末步 generation loss 0.481。

**生成 EM**：

| | val (32) | test (64) | all (96) | 列表内误选 | 列表外乱生成 |
|---|---|---|---|---|---|
| B1 原版 GRIP | 46.9% | **53.1%** | **51.0%** | 26 | 21 |
| listed 对比 | 50.0% | 40.6% | 43.8% | **1** | **53** |
| Δ (listed − B1) | +3.1 pp | −12.5 pp | **−7.3 pp** | −25 | +32 |

**判读**：

1. 对比目标本身是有效的：列表内误选从 26 降到 1，candidate loss 收敛到近 0。
2. 代价是解码跑出 10-way：列表外错误从 21 涨到 53。模型学会「别选这 9 个干扰项」，但没有学会「只在这 10 个里答」——约一半 quick01 错误本来就是 OOV，对比 loss 不覆盖它们，还可能把概率质量推到列表外。
3. H1 在 smoke 上 **未过门**：生成 EM 掉了 7.3 个点，超过方案里「EM 掉幅不超过 2 点」的 gate。
4. 这是 64 条 QA 的 smoke，val/test 方向还不一致（val 微涨、test 大跌），**不能外推，也不能当阴性论文结论**。只能说明：按当前 λ=1、无约束解码，listed 对比会牺牲生成。

## 6. 尚未做的

- Pilot 规模（512/128/512）的 listed vs B1 **没有跑**。
- 原方案 B2–B10（random / uniform / tail_range / path / 三家族 / adapter loss）**按当前证据不应开**。
- Stage D adapter 身份对比、H4 shuffled 控制：NELL23K 单图做不了 shuffled，需要 CLEGR 或多图。
- 约束解码（生成限制在 10-way）或 rollout 挖 OOV 负样本：还没有实现。
- λ_candidate 扫描、计算量匹配（listed 多 6400 次候选前向）未做。

## 7. 汇报时建议怎么讲

1. **问题**：GRIP 把图写入 LoRA 后，生成式关系预测仍有大量列表内混淆和 OOV；我们想用硬负样本对比把正确答案和易混关系拉开。
2. **先证伪、再转向**：按图结构造的负样本，模型并不觉得更难，也几乎不等于它会犯的错。真正的决策集合是题目上的 10-way，外加一批近形 / OOV 解码错误。
3. **转瞄准点之后训了一枪**：listed InfoNCE 把列表内错误几乎打掉，但生成 EM 下降——错误转移到列表外。对比学到了「别选这 9 个」，没有学到「给出正确关系」。
4. **当前判断**：结构负样本路线停；listed 对比不是免费增益。下一步若继续，优先诊断「如何在压列表内混淆的同时不把解码推出词表」，而不是加数据或开 B2–B10。
5. **定位诚实**：这是对 GRIP 的 analysis + extension。listed 硬度是协议卫生，不是方法贡献。方法贡献取决于生成 EM 能否超过原版 GRIP。

## 8. 可选下一步（需拍板）

按成本从低到高：

1. **诊断 smoke 失败模式**（推荐，几乎不占 GPU）  
   对照 B1 / listed 的 96 条预测：OOV 是否前缀混淆、是否 λ=1 过大把概率质量推出 10-way。可直接写进当前结论。
2. **约束解码或降低 λ**  
   生成时限制在 10-way，或 λ∈{0.1, 0.3} 再跑同一份 s1_adapter。验证「对比有效 + 生成不崩」是否可兼得。
3. **同一配方上 pilot 512/128/512**  
   仅当 2 在 smoke 上 EM 不掉超过 2 点时再开。现在开是浪费。
4. **转机制分析（路线 B）**  
   不依赖负样本硬度，做 correct vs none adapter 的分数分解。前置已经部分成立（47.8% vs 22.5%），但 H4 的 shuffled 控制仍缺多图。

**不建议**：重训 path/tail_range；把 64 题 smoke 的 −7.3 pp 写成论文阴性结果；在 OOV 未处理时宣称 listed 对比「有效」。
