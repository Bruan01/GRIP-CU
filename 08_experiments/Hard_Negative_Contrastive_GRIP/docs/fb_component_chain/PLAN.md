# 有界后台接续：Violation-only → Profile-only → 四行消融表

授权：用户要求盯住当前实验，结束后继续下一步。下一步限定为之前讨论的Profile-only单组对照；不自动扩展到更多seed、HPO、数据集或其他实验。

## 顺序与预算

1. 当前Violation-only继续独立的32步训练及一次10,000题测试，不改动其冻结执行代码。
2. 同时仅在CPU准备Profile-only：结构权重1、违例权重0；其余与既有Full/Random/Violation相同。精确重放Full bank后冻结新候选库。
3. 当前Violation-only完整结束、进程正常退出、原始预测和模型/产物身份审计通过后，等待GPU空闲，再启动唯一Profile-only运行。
4. Profile-only仍为seed2026、32步/120步调度，只做一次完整测试，不全量验证、不新调参。预计新增约6–7小时。
5. Profile-only结束并通过同样审计后，汇总Random / Profile-only / Violation-only / Full四行表、逐题CSV及配对差；守护自动结束，不启动第三个新实验。

无论Violation-only分数高于、等于或低于Full，都执行这个预定Profile-only对照，以免按测试方向挑选实验。当前实验的执行或完整性失败则停止接续，保留现场与失败原因；不自动重试、修改预算或继续下一组。

## 这一步为论文补什么

- Full − Violation-only：在B1反馈基础上，结构项的条件性增量。
- Full − Profile-only：在图统计画像基础上，B1反馈的条件性增量。
- 两个单信号组各自对Random：区分哪种信号提供了观测收益。

最终叙事根据四行结果决定。单seed和既有SC-CL选定配置的局限保留；四行表本身不提供跨seed显著性或普适协同证明，不因表格齐全就宣称“两者缺一不可”。

## 守护机制

- 每30秒记录阶段、进度和会话状态；独立tmux与队列文件锁防止重复监控/启动。
- 仅在前序status完整完成、会话退出、冻结输入/代码、32/120预算、测试权重身份、10,000题完整正确标记和归档SHA-256核验后放行。
- GPU有其他计算任务时等待，不结束或抢占其他进程。
- Profile-only启动前再次验证准备好的contract与CLI；启动回执持久保存。同一队列恢复时只接管已有会话或结果，不重复启动已失败或已完成的训练。
- 守护、两组实验的所有日志、配置、模型、检查点、optimizer/RNG、原始预测和论文产物均保留。
- 四行汇总只新增结果文件，不自动改写论文主文或执行远程推送。后续交互中再按仓库阶段性规则提交经过核验的结果。
