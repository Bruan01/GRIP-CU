# FB15K237-2 单种子、固定配置 Random-9 对照

状态：代码与 CPU 核验已完成，单次后台实验已启动；尚无 Random-9 完整测试结果。具体运行身份和目录见 `RUN_RECORD.json`，实时阶段以Linux运行目录的 `status.json` 为准。

研究问题：在已获选 SC-CL 的训练配置下，将结构画像与 B1 违例度的组合采样换成同合法池均匀采样，直接解码性能如何变化？这检验固定配置下组合候选选择的增量，不单独证明结构信号，也不构成双方等预算调参后的最优性能比较。

## 已固定的范围

- 数据集 FB15K237-2；唯一训练/采样 seed=2026。不做重复种子或新超参搜索。
- 父运行：已归档的 trial1/step32，测试 EM=89.90%，对应 10,000 题；当前匹配 B1 为81.87%。这两个数仅作为既有参考，不是新结果。
- 复用父运行 Stage1 权重、已修复的全部12,136条训练QA，其中3,109条参加候选损失；保留464条训练关系QA修复条件。
- 匹配 LoRA r=24/alpha=48、模型精度、有效batch、优化器及epsilon、学习率、权重衰减、候选损失权重/温度、数据顺序、生成目标、提示和测试十候选。
- 只替换训练候选身份；每题 K=9，从与原 SC-CL 完全相同的训练合法关系池均匀无放回抽样，先冻结再训练。保留原候选库只读。
- 实际训练32优化步；保持原5-epoch线性调度，父Trainer max_steps=120。不能把调度压缩到32步。
- 预先固定使用第32步模型，不根据新验证/测试结果追加训练、重采bank或选其他步。
- 主指标完整测试直接解码EM及逐题配对净变化。MRR/Hits需要另行候选评分，本轮不隐含增加该GPU预算。

## 最小实现映射

1. 在现有训练入口加入独立 `frozen_random` 候选来源，复用相同损失与QA数据路径。
2. 新增可审计均匀bank构造与训练配置匹配工具，核对原始train-known过滤和原score dump的合法池一致。
3. 新增分阶段入口：CPU准备、训练、验证/固定模型测试、论文汇总与产物清单。默认仅准备；训练/推理必须显式选择阶段。
4. 保留代码与输入快照、hash、命令、日志、环境、所有训练检查点和Trainer历史、模型与优化器状态、逐题输出、配对CSV、方法差异表、论文表格及证据索引；不自动清理或覆盖父结果。
5. 用小型合成fixture检验采样、错配拒绝、恢复和汇总，再对真实FB数据做CPU准备与训练CLI连通性验证。合成测试不作为研究证据。

## 执行与资源边界

执行环境为项目 guardenv 的Python；设备为单张RTX3090 24GiB。训练按父运行microbatch=1、accum=512串行执行。权重和检查点保留在Linux运行目录，尽量复用只读输入；不复制基础7B权重。正式训练时记录实际软件版本、显存快照、墙钟时间与存储情况。用户已追加授权在代码通过验证后开始这一次实验；已启动冻结代码的串行后台流程，不做额外训练重复。

## 验收与停止规则

- CPU验收：bank覆盖3,109题、每题9个互异合法候选；生成QA及前缀不变；所有非候选训练字段匹配；父模型、输入及参考预测身份可追溯。
- 训练验收：同一运行目录可续跑；修改配置、输入、代码或bank后禁止混用已有检查点；32步后停止；保留120步调度身份。
- 结果验收：完整10,000题ID/提示/答案对齐，按项目normalization重算EM；输出SC-CL相对Random-9的纠错、退化及净差；无结果时明确pending，不填写估计分数。
- 只描述单seed、固定配置的条件性差异；无多seed显著性或因果协同主张。负结果也完整保存。
- 论文映射：`SC_CTRL_RANDOM`、主张`C2`、实验节候选来源消融；代码准备完成不把实验矩阵标成observed。
