# FB15K-237 第二数据集实验

目标：检验在 NELL23K 上观察到的 Random-K 对比训练收益能否在另一数据集上复现。这是同一训练方法在第二数据集上重新训练的实验，不是把 NELL23K 适配器直接迁移到 FB。

## 固定协议

- 原始数据：272,115 条 train，17,535 条 valid，20,466 条 test；237 个关系 ID，经原始映射后为 233 个不同答案文字（与原处理器一样对文字去重）。
- 图记忆和任务生成只使用 train 三元组，推理任务的参考问答也来自 train。valid/test 标签不进入任务生成。
- 实体文字和关系描述沿用原始 GRIP 的 FB15K-237 处理方式。
- 验证和测试分别固定抽取 10,000 题，每题正确关系加 9 个训练关系词表随机干扰项。按照原处理器先 valid 后 test 的顺序生成候选再抽题，NumPy RandomState seed=2026。
- 原处理器将 Python set 直接转成 list，候选顺序随哈希种子变化。本实验显式排序关系文字并记录完整顺序及文件 SHA-256，因此采用相同采样规则，但不声称逐题复现历史候选列表。
- smoke 是固定全量评测题中每个 split 的 96 题，只用于流程检查；最终比较使用 10,000 validation + 10,000 test，并分别报告。

## 模型与比较

Qwen2.5-7B-Instruct，MLP-LoRA r=4、alpha=8，作用于 down/up/gate projection。新训练 FB 的共享 S1，随后分叉：

| 分支 | 训练目标 |
| --- | --- |
| B1 | 生成损失 |
| Random-K（目录名 listed） | 同样生成损失 + 9 个训练关系随机负样本的对比损失，lambda=1 |

任务配额：context QA 8,000，reasoning QA 2,000，summarization 6,000；最终有效条数取决于生成和解析。生成 batch=1，以适配 24GB GPU。S1 1 epoch、原有 loss threshold=0.15，S2 两组各 10 epochs，batch=1、梯度累积=512、学习率 1e-3。S2 不以混合损失提前停止。

评测同时输出 greedy generation EM、闭集十选一 EM，以及生成答案候选外比例。先比较相同解码方式的 B1 与 Random-K。

接入时修复了通用图清理函数：删除自环或重复边后，后续保留边必须索引原始位置的文字，避免节点编号与文字错配；保留原函数按节点对去重的语义。该修复同时用于本实验两组任务。

## 启动与恢复

在实验目录执行：

```bash
bash configs/run_fb15k237_second_dataset.sh
```

默认 session：`fb15k237-b1-randomk`。

默认固定运行目录：`results/runs/20261015_fb15k237_qwen7b_b1_randomk/`。

```bash
tmux attach -t fb15k237-b1-randomk
```

主日志为运行目录下 `run.log`。启动脚本依次执行数据处理、任务生成、CPU 负样本检查、共享 S1、两组 S2、全量两种解码，并保留 `experiment_plan.json`。生成配置和原始文件哈希发生变化时拒绝复用同一运行目录。

任务生成每完成一个 batch 就追加 JSONL 缓存。训练每 10 optimizer steps 保存 checkpoint，仅保留最近 2 个；重启会自动恢复 `trainer_s1`、`trainer_b1`、`trainer_listed` 下 checkpoint，已完成适配器自动跳过训练。所有评测按 question_id 续写预测。重复执行相同启动命令即可恢复；已有同名 tmux session 时只提示 attach，不会重复启动。同一 RUN_DIR 另有文件锁防止不同 session 抢占。

数据准备清单在 `data/fb15k237/preparation_manifest.json`，生成的大型本地数据、任务缓存和模型权重不提交 Git。
