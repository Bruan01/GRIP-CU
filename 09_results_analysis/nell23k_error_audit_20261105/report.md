# NELL23K：现有反事实对比学习的错误规律与调参空间

分析日期：2026-11-05。结论：**仍有针对性涨点的可能，最值得优先验证的是现有采样器的负例难度，而不是继续机械地降低损失权重或延长训练。现有证据不能保证测试涨点，也不能估计一定能涨几个百分点。**

本次只读取既有预测、训练关系与冻结 B1 打分，在 CPU 上复算错误、配对变化和采样敏感性。没有启动训练或推理，没有更改方法、权重、原候选库或已关闭搜索。原冻结测试仍是 **4340/4943，87.800931%**。

## 1. 错误集中在哪些地方

主分析对象为原 trial1、Stage2 第32步模型。验证和测试分别分析；虽然预测文件中两者都使用 `0:test:*` ID，已逐条与各自 processed 源文件核对，未跨集合连接。

| 关系标签 | 验证错题/题数 | 测试错题/题数 | train图边数 | 实际参与对比学习的训练QA数 |
|---|---:|---:|---:|---:|
| `proxyfor` | 74/159 | 71/162 | 868 | 94 |
| `mutualproxyfor` | 62/102 | 67/99 | 586 | 70 |
| `subpartof` | 80/138 | 63/117 | 673 | 78 |
| `synonymfor` | 21/22 | 22/25 | 101 | 6 |
| `subpartoforganization` | 23/46 | 18/44 | 345 | 36 |

前三类合计只占测试378/4943题（7.65%），却贡献201/603个错误（33.33%）；这三类准确率46.83%，其余关系91.19%。验证中也呈现相同集中：399题错216题。它们在 train 中并不稀少，所以不能把主要瓶颈归因于长尾关系。

`synonymfor` 则同时存在训练对比QA少、验证和测试都很差的问题。它值得监测，但测试只有25题，不能据此推导整个数据集都需要少样本重采样。按实际对比QA数量分组，错误率也没有随样本数单调变化；关系身份与任务难度在这里相互混杂。

## 2. 候选外输出是突出问题，但并非全部问题

原模型603个测试错误中：

- 423个是在给定候选内选错，占70.15%。
- 180个输出了题目候选以外的关系，占29.85%。
- 这180个中，102个属于train关系词表，78个连train关系词表也没有。
- 180个全部有完整 `<answer>` 标签，且输出都符合 `concept:...` 关系名形式。这里不是漏标签、乱码或空输出问题。

验证的611个错误中也有169个候选外输出，其中83个不在train关系词表。各题金标准均已确认包含在题目给定候选中。

最典型的验证样本：

| 验证ID | 金标准 → 模型输出 | 可检查的现象 |
|---|---|---|
| `0:test:332` | `proxyfor` → `citylocatedinstateorprovince` | Turlock与California；输出关系不在本题候选中，也不在train关系词表中 |
| `0:test:866` | `teamplaysagainstteam` → `agentcompeteswithagent` | 两支球队；两个标签都在候选中，发生具体关系与更一般关系的混淆 |
| `0:test:447` | `synonymfor` → `companyeconomicsector` | GM与General Motors的实体字符串；两个标签均在候选中 |
| `0:test:809` | `subpartof` → `agentcontrols` | 两个标签均在候选中，模型未恢复该题指定图关系 |

验证中仅 `proxyfor → citylocatedinstateorprovince` 就出现22次。该输出不属于train关系词表，所以当前train词表内的反事实采样器无法直接把它采为负例；改变采样权重能否间接抑制这类输出仍未知。

这些例子与“模型倾向依据实体名称猜一个熟悉关系，而没有恢复图中特定标签”的解释相容；这是错误样本支持的机制假设，不是已证明的因果机制，也不是对金标准错误的判定。当前方法没有对这些样本保存可用于诊断的完整候选分数，不能断言金标准均在top2或仅差一点分数。

## 3. 已做调参给出的正、负证据

| 既有配置 | 完整验证正确数/4950 | 完整测试正确数/4943 |
|---|---:|---:|
| 原模型，第32步 | 4339（87.6566%） | 4340（87.8009%） |
| 从第32步低学习率追加32步 | 4363（88.1414%） | 4337（87.7402%） |
| 从固定Stage1重新训练，λ从0.1123降到0.05 | 4335（87.5758%） | 未测试 |
| 从固定Stage1重新训练，学习率从9.476e-4降到6e-4 | 4353（87.9394%） | 未测试 |

追加训练显式重置了优化器和数据游标，所以它是续训探索，不是原优化器轨迹的精确延续。

原方法相对同提示B1在测试中修正321题，同时让162道原本答对的题答错，净增159题。这说明“保住已有能力”也是调参目标，不能只追求更强区分。

追加低学习率训练修正107个原模型测试错误，却又退步110题。候选外错误从180降到150，但候选内错误从423增到456，最终少对3题。类似地，λ=0.05使验证候选外错误从169降到123，候选内错误却从442增到492，总计少对4题。**减少候选外输出，并不自动意味着EM上涨。**

四组已有配置（原32步、追加训练、低λ、低学习率）共同答错440道验证题，其中 `subpartof / proxyfor / mutualproxyfor` 占187道。这表明当前局部参数邻域有稳定难点；它不是整个方法的不可突破上限。已有测试暴露及验证few-shot使用记录仍保留，本分析属于开发诊断。

## 4. 更值得试的现有超参数：采样权重

当前冻结负例库共2974个训练QA、每题9个负例，共26766个。使用生产采样器、相同seed及train-known-pair过滤，重新采样能够逐题完全复现当前负例列表。

当前负例中，67.21%在冻结B1的全关系候选排名第50名以后；68.79%的分数低于金标准至少2个现有打分单位。这说明采到了大量B1已经较容易区分的关系。这里的“难度”是冻结B1上的代理指标，不代表当前SC-CL模型上的难度或梯度贡献。

离线只调整一个已有采样超参数，其余保持当前值：

| 单项改动 | 负例中B1排名前10占比 | B1排名50名后占比 |
|---|---:|---:|
| 当前：violation_weight=1，ρ=1/3，采样温度0.25 | 8.38% | 67.21% |
| violation_weight=2 | 15.36% | 57.46% |
| violation_weight=4 | 29.42% | 45.26% |
| ρ从1/3降到1/6 | 9.59% | 64.78% |
| 采样温度从0.25降到0.15 | 13.17% | 60.29% |

**这验证了现有超参数确实能提高选中负例在B1上的难度，尚未验证EM提高。** 所有方案均使用同一批冻结训练打分、同一结构相似度、同一公式和K=9，没有把验证/测试错题注入训练。并未创建或替换正式负例库。

实现还有一个需要区分的细节：打分文件已保存 `pairwise_confusion`，采样器优先使用该值；所以本次降低采样温度主要改变softmax选择分布，并未重新计算B1混淆值。**采样温度0.25与InfoNCE损失温度0.8864是两个不同参数。**

## 5. 不改变方法前提下的优先级

1. **第一优先：单独调 violation_weight，先2，必要时4。** 保留结构权重1、ρ=1/3、采样温度0.25、K=9；保留原Stage1、种子、λ=0.1123、InfoNCE温度0.8864、学习率与步数作比较。已有训练打分可以复用。支持理由是上表实测采样变化；收益和更难负例带来的退步风险都需要验证集测量。
2. **第二优先：InfoNCE温度的两侧敏感性，例如0.6与1.2。** 这是未验证的候选值。固定一个负例库和其余超参数，分别观察更尖锐/平滑的损失能否减少具体/一般关系混淆。温度同时影响区分形状与梯度尺度，不能简单理解为“越低越好”，也不宜与第一项混在同一对照里解释。
3. **第三优先：围绕有效配置细化步数及学习率。** 最近低学习率试验和追加训练没有带来新的测试提升；不把更长训练、更小学习率作为默认答案。λ=0.05的完整验证已有负结果，继续向下盲搜的优先级低。

现阶段不优先扩大K、改LoRA结构或重新生成任务；前者会增加候选打分训练成本，后两者超出本次限定的最小调参范围。候选约束解码、候选重排、同义词后处理可能改变评测行为，也不作为本结论中的“原方法调参收益”。

下一轮如执行，应另外冻结预算，以完整4950题验证EM为主，1000题子集只用于预筛；同时记录前三类关系错误、候选内/外错误以及相对原模型的rescue/regression。不得只凭某一错误桶下降选模型。已有完整验证最好为4363题；例如沿用净增至少10题的标准，晋级需至少4373题，而非仅超过原模型的4339题。模型锁定后再做一次测试，并保留所有负结果。

本次分析到此结束；没有自动重开旧搜索。对“能涨多少”没有可靠估计，603个错误数也不能当成可恢复空间。
